# 第四章：首次对话

::: tip 学习目标
学完这章，你能开一个会话、问出好问题，并知道 `Shift+Tab`、`/init`、`/context` 这三个最常用的入口。
:::

## 启动对话

在项目文件夹里打开终端，然后：

```bash
cd 你的项目文件夹
claude
```

::: tip 为什么要 cd 到项目里
Claude Code 的工作范围就是**你启动它的那个文件夹**。在 `~` 目录下启动，它看不到你的项目。养成"先 cd 再 claude"的习惯。
:::

### 你好！

直接用中文问：

```
你好，Claude！
```

它就会用中文回复你。

## 三个要立刻记住的操作

新手期只需要这三个，其他都可以以后再说。

### 1. `Shift + Tab` —— 切换它问不问你就动手

按一下 `Shift + Tab`，输入框下方会显示当前权限模式。默认是**自动模式**：读文件、跑测试这类安全操作它直接做，删文件、push 到远端这类危险操作会拦下来问你。

不确定它在干什么的时候，切到"每次都要问"的模式，看完几轮再切回来。详见第十七章。

### 2. `/init` —— 让它先认识你的项目

第一次在某个项目里用它，先运行：

```
/init
```

它会读一遍你的项目，生成一个 `CLAUDE.md`，把技术栈、常用命令、目录约定记下来。**以后每次开会话它都会自动读这个文件**，省掉反复解释。这是投入产出比最高的一步。

### 3. `/context` —— 看它现在脑子里装着什么

对话变长以后，运行：

```
/context
```

它会显示上下文窗口被什么占满了（文件、工具输出、记忆），并告诉你哪些地方在浪费空间。满了就会变慢、变笨，这时候用 `/compact` 压缩，或 `/clear` 重开。

## 退出对话

三种方式：

1. 输入 `/exit` 并回车
2. 连按两次 `Ctrl + C`
3. `Ctrl + D`

::: tip 关掉 ≠ 丢掉
会话会自动保存。下次想接着聊，运行 `claude --continue` 接着上一次，或 `claude --resume` 从列表里挑一个。详见第七章。
:::

## 怎么问问题效果最好？

### 模糊 vs 具体

| 效果不好的问法 | 效果好的问法 |
|--------------|-------------|
| "代码有问题" | "这个函数报 TypeError: Cannot read property 'x' of undefined" |
| "帮我看看" | "帮我看看 `src/calc.js` 里的 `calculateSum` 函数" |
| "能帮我吗" | "写一个计算两数之和的函数，放在 `src/calc.js`，加个测试" |

越具体，它要猜的东西越少，回答越准。

### 它看不见的东西，得你告诉它

它读不到你脑子里的东西：为什么要做这个改动、哪个文件绝对不能动、部署流程是什么。这类信息要么写进 `CLAUDE.md`，要么在提问时直接说。

### 给它一个能自己检查的办法

比"改对了吗？"更有效的是"跑一下 `npm test` 看是否通过"。有可验证的标准，它就能自己迭代到正确。

## 常用提问示例

### 理解代码库

它会按需自己读文件，你不必手动粘贴代码：

```
这个项目是做什么的？
```

```
这个项目用什么技术栈？主入口在哪里？
```

```
解释一下目录结构，哪些是核心代码
```

```
用户的登录流程是怎么走的？从哪个路由进来？
```

### 动手改

```
帮我给 hello.py 加个命令行参数，默认输出当前时间
```

```
这段代码哪里有 bug？先解释原因，再给修复方案，我来决定用哪个
```

### 其他常见问题

```
帮我解释一下 src/utils.js 这个文件
```

```
把这个目录下的文件名按 日期_标题.md 的格式批量重命名，先列个清单给我看
```

## Claude 的回答格式

它的回复通常包含：

1. **解释**：它在做什么、为什么
2. **改动**：编辑文件时会显示 diff（新增绿、删除红）
3. **建议**：还能怎么改进

改文件时它会**请求许可**（自动模式下，安全改动直接执行）。看到 diff 别急着按回车，扫一眼再放行。

## 常见问题

**Q: 回答很慢？**

A: 正在生成，稍等。长任务可以按 `Esc` 中断，然后让它"先给计划，别动代码"。

**Q: 回答被截断了？**

A: 输入「继续」，让它说完。

**Q: 答非所问？**

A: 换个更具体的问法，或者直接 `@` 指定文件，比如 `@src/auth.js 这里的超时是怎么设的？`

**Q: 它说改了，但我没看到变化？**

A: 运行 `/diff` 看它到底改了什么。如果什么都没改，说明它只是描述方案没动手，直接说「按这个方案改」。

**Q: 改坏了怎么办？**

A: `/rewind` 可以回滚代码和对话到任意一个检查点。这是最常用的后悔药。

## 练习题

1. 在任意项目里运行 `claude`，问「这个项目是做什么的？」
2. 运行 `/init`，打开生成的 `CLAUDE.md` 看看它写了什么，删掉不对的部分
3. 按 `Shift + Tab`，观察输入框下方的模式提示怎么变
4. 运行 `/context`，看当前的上下文占用

## 入门篇总结

到这里你已经能跑起来了。回顾一下手上的工具：

- **装好了** `claude`（第二章）
- **配好了**账号（第三章，官方订阅或中转）
- **会开话术**：`cd` → `claude` → 提问
- **三个入口**：`Shift+Tab`（权限）、`/init`（认识项目）、`/context`（看上下文）
- **一个后悔药**：`/rewind`
