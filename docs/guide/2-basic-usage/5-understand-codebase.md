# 第五章：读懂代码库

::: tip 学习目标
学完这章，你会让 Claude 帮你分析和理解现有代码，掌握大项目分析策略。
:::

## 为什么让 AI 读代码更快？

想象你要接手一个陌生人的项目：

- 自己读：可能需要几天
- 让 Claude 读：几分钟就能了解大概

Claude 可以快速理解代码结构，帮你回答"这个项目是做什么的"、"某个函数在哪里"等问题。

## 小项目分析

### 基本流程

```bash
cd 你的项目路径
claude
```

然后直接问：

```
请分析一下这个项目的结构
```

Claude 会读取目录下的文件，告诉你项目的基本情况。

## 大项目分析策略

当项目有数十甚至数百个文件时，一次性分析会：
- 消耗大量 Token
- 产生过多无关信息
- 分析速度很慢

**正确策略：分层探索**

### 第一步：找入口点

```
这个项目的入口文件是哪个？
```

入口文件通常是：
- `main.py` / `main.js` / `main.ts`
- `app.py` / `app.js` / `App.tsx`
- `index.js` / `index.ts`

### 第二步：理解模块划分

```
这个项目有哪些主要模块？
```

### 第三步：逐个深入

```
先看看 auth 相关模块是怎么实现的
```

### 第四步：追踪调用链

```
这个函数在哪里被调用了？
```

## 问更具体的问题

### 问单个文件

```
这个 main.py 的主要功能是什么？
```

### 问某个函数

```
帮我理解 utils.py 里的 helper 函数
```

### 问整体架构

```
这个项目是怎么组织的？有哪些主要模块？
```

### 问依赖关系

```
这个模块依赖哪些其他模块？
```

### 问调用链路

```
从入口到这个函数，调用链是怎样的？
```

## 上下文管理

### 短对话 vs 长对话

| 场景 | 建议 |
|------|------|
| 探索性分析 | 短对话，问完就结束 |
| 深入理解 | 长对话，保持上下文 |
| 超过 50 条消息 | 开新对话 |

### 开新对话的时机

- 对话超过 50 条消息
- 换了完全不相关的任务
- 想重新分析

### 交接上下文

换对话时，简要描述背景：

```
我在分析一个 Flask 博客项目，已经知道：
1. 使用 JWT 认证
2. 文章存在 PostgreSQL
3. 有用户和评论模块

现在要了解评论功能实现...
```

## 实际案例

### 场景：接手一个博客项目

**第一轮：快速了解**

```
你：这个项目是做什么的？
Claude：这是一个博客系统，使用 Python Flask 框架...

你：入口文件在哪里？
Claude：入口文件是 app.py...

你：有哪些主要模块？
Claude：auth（认证）、post（文章）、comment（评论）...
```

**第二轮：深入某个模块**

```
你：用户认证是怎么实现的？
Claude：在 auth.py 文件里，使用 JWT token...

你：JWT 密钥在哪里配置？
Claude：在 config.py 的 SECRET_KEY...
```

### 场景：理解调用链路

```
你：追踪一下用户发表评论的完整流程
Claude：
1. 用户提交评论 → routes/comment.py:create()
2. 验证权限 → middleware/auth.py:require_login()
3. 保存到数据库 → models/comment.py:Comment.create()
4. 发送通知 → services/notification.py:send_email()
```

## 前置知识

知道什么是代码文件（.py, .js 等）。

## 常见问题

**Q: Claude 读错了？**

A: 确认你在正确的目录下，用 `pwd` 查看当前位置。

**Q: 大项目分析很慢？**

A: 先指定具体文件，不要一次性分析整个项目。按入口→模块→细节的顺序探索。

**Q: 对话太长了怎么办？**

A: 输入 `/clear` 清空对话，或开新对话并简要描述背景。

**Q: Claude 忘了之前说的？**

A: 可以在对话开始时说"/memory"查看记忆，或重新描述上下文。

3. 测试开新对话时的上下文交接
