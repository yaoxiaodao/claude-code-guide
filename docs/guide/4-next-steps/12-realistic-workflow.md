# 第十二章：日常工作流实战

::: tip 学习目标
整合前十一章所学，体验一个完整的 AI 辅助开发工作流。
:::

## 本章内容

这一章不教新功能，而是把前面学到的技能串联起来，通过三个真实场景体验完整的工作流。

每个场景都是独立的小练习，你可以选择一个或多个来完成。

---

## 场景一：接需求 → 写代码 → 自测 → 提交

这是最常见的日常场景。

### 需求描述

> "帮我在博客系统里加一个功能：显示每篇文章的阅读量。"

### 完整流程

**第一步：理解需求**

```
你：帮我看看现有的博客系统结构，了解一下文章相关的代码是怎么组织的。
Claude：（分析项目结构，给出代码概览）
```

**第二步：设计实现方案**

```
你：这个功能应该怎么实现比较合理？
Claude：（给出方案建议，包括数据库改动、代码逻辑、模板更新）
你：好，就按你说的方案来
```

**第三步：让 Claude 写代码**

```
你：帮我实现这个功能，需要修改哪些文件？
Claude：（逐个修改文件，每次修改前会询问你确认）
```

**第四步：自测**

```
你：功能写完了，帮我测试一下
Claude：（指导你如何测试，可能需要手动访问页面验证）
```

**第五步：提交代码**

```
你：帮我写 commit message 并提交
Claude：（生成规范的 commit message）
```

## 场景二：接手旧项目 → 理解代码 → 修 bug

接手的项目不熟悉？Claude 帮你快速理解。

### 需求描述

> "我接手了一个旧项目，有人在里面埋了个 bug，需要我找出来并修复。"

### 完整流程

**第一步：了解项目**

```
你：这个项目是做什么的？帮我分析一下结构
Claude：（介绍项目类型、技术栈、目录结构）
```

**第二步：找到问题代码**

```
你：这个项目有个 bug，用户反映【具体问题描述】
Claude：（分析可能的问题位置）
```

**第三步：定位并修复**

```
你：帮我看看这几行代码是不是有问题
Claude：（分析后给出结论）
你：确实是这里的问题，帮我修复
Claude：（修改代码）
```

**第四步：验证修复**

```
你：帮我再检查一遍，确保没有引入新问题
Claude：（审查代码，确认修复正确）
```

## 场景三：代码审查 → 优化 → 完成

用 Claude 做 Code Review 是个很好的习惯。

### 需求描述

> "我写了一段代码，想让 Claude 帮忙审查一下有没有问题，然后优化一下。"

### 完整流程

**第一步：提交代码审查**

```
你：请审查 `routes.py` 中的用户认证相关代码
Claude：（逐个指出潜在问题、安全风险、优化建议）
```

**第二步：逐个讨论**

```
你：第二个问题怎么修复比较好？
Claude：（给出具体修复方案）
你：好，帮我改一下
Claude：（修改）
```

**第三步：优化建议**

```
你：除了 bug 修复，还有哪些可以优化的地方？
Claude：（从性能、可读性、安全性等角度给出建议）
```

**第四步：实施优化**

```
你：帮我把重要的优化实施了
Claude：（逐一修改，每次确认）
```

## 练习题

从下面三个场景中选一个，用 Claude 完整走一遍：

1. **场景 A**：给博客加一个"评论功能"（从设计到实现到测试）
2. **场景 B**：找一个开源项目，用 Claude 分析它的架构和代码
3. **场景 C**：把自己的某个旧项目交给 Claude 做全面代码审查

## 常见问题

**Q: 遇到 Claude 理解错了怎么办？**

A: 越具体越好。把错误信息和上下文一起给 Claude，它会更准确地定位问题。

**Q: 场景太复杂，跟不上怎么办？**

A: 把大任务拆成小任务。Claude 每次只做一件事，出错的概率就会降低。

**Q: 担心 Claude 写错代码？**

A: 这是正确的谨慎。每次修改前 Claude 都会给你确认机会，最后运行代码的也是你自己。
