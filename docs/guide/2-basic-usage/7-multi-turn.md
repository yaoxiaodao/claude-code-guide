# 第七章：上下文与会话管理

::: tip 学习目标
学完这章，你能自己判断「该压缩还是该重开」，会用 `/resume`/`/rewind` 找回之前的任何状态，也知道怎么让多轮对话真正收敛到结果。
:::

## 为什么多轮对话更有效？

想象你要建一座房子：

- **一次性描述**：给我建一座房子 → 出来的可能不是你想要的
- **一步步来**：先打地基 → 地基好了继续砌墙 → 墙好了继续装修 → 每一步都能调整

多轮对话就是这种方式。但它有个前提：**Claude 的"记忆"是有容量的**，这个容量叫上下文窗口。管不好它，多轮就会变成越聊越糊涂。

## 场景演练：做一个待办事项

### 第一轮：基础结构

```
帮我写一个待办事项的基本结构，先用 Python 命令行版本
```

### 第二轮：添加功能

```
添加"标记完成"功能，已完成的项目在最上面
```

它会基于现有代码继续改，不用你重新解释。

### 第三轮：加一个可验证的标准

```
加上单元测试，跑 pytest 全绿了再告诉我
```

::: tip 关键习惯
每一轮都给它一个**能自己检查的标准**（测试通过、命令输出、lint 无警告）。有标准它会自己迭代到对；没有标准它只能说"我改好了"，而它可能没改好。
:::

## 上下文窗口到底装了什么

运行 `/context` 看实时占用。装的东西大致是：

| 占位来源 | 说明 | 能不能省 |
|---|---|---|
| 系统提示与工具定义 | 它自己的说明书，固定开销 | 不能 |
| `CLAUDE.md` 与记忆 | 每次会话自动加载 | 能，写短点 |
| 你读过的文件 | 读一次就留在窗口里 | 能，用 `@` 精确指定 |
| 工具输出 | 测试日志、命令结果，往往最占地方 | 能，让它只输出摘要 |
| 对话历史 | 你的提问和它的回复 | 靠压缩 |

::: warning 别让一条命令撑爆上下文
`cat 一个 10 万行的日志` 会直接把窗口吃掉大半。正确的做法是让它先 `grep` 或 `tail -200`，或者你自己在终端筛完再贴给它。
:::

## 什么时候压缩，什么时候重开

| 你的情况 | 用哪个 | 效果 |
|---|---|---|
| 还是同一个任务，只是聊长了 | `/compact` | 把历史总结成摘要，继续干 |
| 换了个不相关的任务 | `/clear` | 清空对话，保留 `CLAUDE.md` 和记忆 |
| 想回到某个之前的状态 | `/rewind` | 回滚代码 + 对话到检查点 |
| 想同时试两个方向 | `/branch` | 从当前对话分叉，原对话不动 |

### `/compact` —— 压缩

```
/compact
```

可以指定重点，比如 `/compact 保留数据库表结构那部分结论`。

Claude Code 默认也会**自动压缩**：窗口快满时自己总结一次。自动压缩经常触发、感觉越压越糊涂时，说明这个任务该拆了，或者你一开始就该用 `/clear` 重开并带上结论。

### `/clear` —— 重开

```
/clear
```

对话清空，但 `CLAUDE.md`、`.claude/` 配置、记忆都还在。换任务时用它，比在旧上下文里硬接着聊干净得多。

::: tip 重开前先留个交接
重开前让它写一段结论，粘到新会话开头：

```
把这个任务的结论和下一步写成 5 行，我要开新会话接着做
```
:::

## 会话能保存、能恢复、能分叉

会话会自动保存在本地，退出不会丢。

| 命令 | 作用 |
|---|---|
| `claude --continue` | 直接接着**当前目录**最近一次会话 |
| `claude --resume` | 打开会话列表，挑一个恢复 |
| `claude --resume 名字` | 恢复指定名字的会话 |
| `/resume` | 在会话里切换到另一个会话 |
| `/branch` | 从当前对话分叉，去试另一个方向 |
| `/fork` | 复制当前对话到后台会话，这边继续干 |
| `/recap` | 生成当前会话的一句话摘要（离开一阵子回来用） |
| `/export` | 导出对话为文本 |

::: tip 给会话起名字
`/clear 结账模块重构` 里的那个名字会成为会话标签，之后在 `/resume` 列表里一眼就能找到。长期项目尤其值得养成这个习惯。
:::

## `/rewind` —— 最常用的后悔药

```
/rewind
```

按 `Esc` 两次也能打开。它能回滚**代码和对话**到之前任意一个检查点，也可以只回滚其中一样。它还能"从这里往后总结"，把中间一大段压缩掉但保留结论。

什么时候用：

- 它改了一大堆，你发现有 3 个文件改错了
- 聊歪了，想回到岔路口重来
- 想砍掉中间那段试错过程，只保留现在的结论

::: warning 一个边界
`/rewind` 管的是 Claude 自己做的改动。你自己在编辑器里手动改的文件不在它的回滚范围内。
:::

## 记忆：`/memory`

```
/memory
```

打开记忆文件编辑界面，可以查看和修改：

- **`CLAUDE.md`**（项目级）—— 团队共享的规则和背景
- **`CLAUDE.local.md`**（个人级，不进 git）—— 你个人的偏好
- **自动记忆** —— Claude 根据自己的更正经验自动记下的笔记，可以在这里查看、删除

关于怎么写 `CLAUDE.md`，第十一章专门讲。

## 高效交接模板

换新会话时，开头给一段背景比让它重新摸索快得多：

```
我在做一个 Flask 博客项目，已经完成：
1. 用户认证（JWT，代码在 app/auth/）
2. 文章 CRUD（app/posts/）
3. PostgreSQL + SQLAlchemy

当前问题：评论功能的权限判断不对，普通用户能看到别人的草稿评论。
先定位原因，给方案，别急着改。
```

比起"帮我加评论功能"，这段背景能让它少读几十个文件。

## 常见问题

**Q: 聊到后面它开始忘事、重复犯错？**

A: 上下文被老内容挤满了。先 `/context` 看占用，再决定 `/compact` 还是 `/clear` 重开。

**Q: 关掉终端会话就没了？**

A: 没丢。`claude --continue` 接着上次，或 `/resume` 挑。

**Q: 压缩之后它忘了我定的规则？**

A: `CLAUDE.md` 和记忆不受压缩影响（它们每次重新加载），只有对话历史会被总结。所以**重要规则一定要写进 `CLAUDE.md`，不要只靠嘴上说**。

**Q: 能不能同时开两个会话做不同的活？**

A: 能。多开终端窗口即可。想隔离同一个仓库的并行改动，用 git worktree，见第十九章。

## 练习题

1. 在一个会话里运行 `/context`，找出占用最大的那一项
2. 干一件小事，退出，再用 `claude --continue` 接着聊
3. 故意让它改错一个文件，用 `/rewind` 回滚
4. 用 `/clear 我的任务名` 开新会话，然后在 `/resume` 列表里找到它
