## 本章内容

这一章不教新功能，而是把前面学到的技能串联起来，通过真实场景体验完整的工作流。

## 场景一：接需求 → 写代码 → 自测 → 提交

这是最常见的日常场景。

### 需求描述

> "帮我在博客系统里加一个功能：显示每篇文章的阅读量。"

### 完整流程

**第一步：理解需求**

```
你：帮我看看现有的博客系统结构，了解一下文章相关的代码是怎么组织的。
Claude：（分析项目结构，给出代码概览）
```

**第二步：设计实现方案**

```
你：这个功能应该怎么实现比较合理？
Claude：（给出方案建议，包括数据库改动、代码逻辑、模板更新）
你：好，就按你说的方案来
```

**第三步：让 Claude 写代码**

```
你：帮我实现这个功能，需要修改哪些文件？
Claude：（逐个修改文件，每次修改前会询问你确认）
```

**第四步：自测**

```
你：功能写完了，帮我测试一下
Claude：（指导你如何测试，可能需要手动访问页面验证）
```

**第五步：提交代码**

```
你：帮我写 commit message 并提交
Claude：（生成规范的 commit message）
```

## 场景二：接手旧项目 → 理解代码 → 修 bug

接手的项目不熟悉？Claude 帮你快速理解。

### 需求描述

> "我接手了一个旧项目，有人在里面埋了个 bug，需要我找出来并修复。"

### 完整流程

**第一步：了解项目**

```
你：这个项目是做什么的？帮我分析一下结构
Claude：（介绍项目类型、技术栈、目录结构）
```

**第二步：找到问题代码**

```
你：这个项目有个 bug，用户反映【具体问题描述】
Claude：（分析可能的问题位置）
```

**第三步：定位并修复**

```
你：帮我看看这几行代码是不是有问题
Claude：（分析后给出结论）
你：确实是这里的问题，帮我修复
Claude：（修改代码）
```

**第四步：验证修复**

```
你：帮我再检查一遍，确保没有引入新问题
Claude：（审查代码，确认修复正确）
```

## 场景三：代码审查 → 优化 → 完成

用 Claude 做 Code Review 是个很好的习惯。

### 需求描述

> "我写了一段代码，想让 Claude 帮忙审查一下有没有问题，然后优化一下。"

### 完整流程

**第一步：提交代码审查**

```
你：请审查 `routes.py` 中的用户认证相关代码
Claude：（逐个指出潜在问题、安全风险、优化建议）
```

**第二步：逐个讨论**

```
你：第二个问题怎么修复比较好？
Claude：（给出具体修复方案）
你：好，帮我改一下
Claude：（修改）
```

**第三步：优化建议**

```
你：除了 bug 修复，还有哪些可以优化的地方？
Claude：（从性能、可读性、安全性等角度给出建议）
```

**第四步：实施优化**

```
你：帮我把重要的优化实施了
Claude：（逐一修改，每次确认）
```

## 场景四：大型重构（进阶）

### 需求描述

> "这个单体应用已经太臃肿了，需要拆分成微服务架构。"

### 完整流程

**第一步：评估现状**

```
你：分析一下这个项目的架构，识别主要的模块边界
Claude：（分析代码结构，识别耦合度高的模块）
```

**第二步：制定拆分计划**

```
你：按模块拆分，这个项目应该拆成哪些服务？
Claude：（给出服务划分方案，包括服务职责、接口设计）
```

**第三步：逐个模块重构**

```
你：先处理用户模块，把它拆成独立服务
Claude：（执行重构，每次修改确认）
```

**第四步：更新调用关系**

```
你：其他模块怎么调用用户服务？
Claude：（更新 API 调用，实现服务间通信）
```

**第五步：测试验证**

```
你：帮我写集成测试，验证拆分后功能正常
Claude：（编写测试用例，覆盖关键路径）
```

## 场景五：跨模块影响分析（进阶）

### 需求描述

> "我修改了 auth 模块，想知道会影响哪些其他模块。"

### 完整流程

```
你：分析一下修改 auth 模块会影响哪些地方
Claude：（追踪调用链，识别所有依赖 auth 的模块）
```

```
你：这些影响中，哪些是 breaking change？
Claude：（分析接口变化，识别潜在破坏性变更）
```

```
你：帮我制定一个安全的修改顺序
Claude：（给出修改顺序，确保依赖关系正确）
```

## 常见问题

**Q: 遇到 Claude 理解错了怎么办？**

A: 越具体越好。把错误信息和上下文一起给 Claude，它会更准确地定位问题。

**Q: 场景太复杂，跟不上怎么办？**

A: 把大任务拆成小任务。Claude 每次只做一件事，出错的概率就会降低。

**Q: 担心 Claude 写错代码？**

A: 这是正确的谨慎。每次修改前 Claude 都会给你确认机会，最后运行代码的也是你自己。

**Q: 大型重构可以用 Claude 吗？**

A: 可以，但建议分步骤进行，每步都要人工确认。不要让 Claude 一次性做太大的改动。
